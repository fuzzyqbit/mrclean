  <behavior>
    Envelope (RESEARCH Pattern 1, verified live): `MRCLNMAP`(8) | 0x01(1) | IV(12) | tag(16) | ciphertext(N); AAD = `mrclean-map-v1:<sessionId>`.
    Cases (all against a per-test tmpdir baseDir, never real ~/.mrclean):
    - roundtrip: writeSessionMapFile then readSessionMapFile => deep-equal map (restorable original survives; secret entry still lacks `original`)
    - fresh IV: two writes => raw envelopes differ in bytes 9..21 (IV) and ciphertext region
    - truncated tag: hand-build an envelope whose total length implies a short tag => read returns null (length pre-validation) — plus a direct decryptMapBuffer unit case proving `authTagLength: 16` rejects a 4-byte tag (DEP0182)
    - tampered: flip one ciphertext byte in a valid file => null (GCM auth fail)
    - wrong AAD: copy <sidA>.map bytes to <sidB>.map and read as sidB with sidA's key material => null (AAD binds sid)
    - wrong key: valid envelope + different 32-byte key => null
    - short file / garbage file / empty file => null
    - valid crypto but non-JSON plaintext => null; valid JSON failing parseSessionMap guard => null
    - map path is a DIRECTORY => null; chmod 000 map file => null (POSIX-only, skip win32 with documented-gap comment per Pitfall 8)
    - missing key file with existing map => null
    - ensureSessionKey: creates 32-byte 0600 key in 0700 dir; second call returns identical bytes (EEXIST loser-reads-winner); dirs created with mode 0o700
    - ciphertext-only on disk: after a write with original 'CANARY-original-xyz' in a WORD entry, raw file bytes contain neither 'CANARY-original-xyz' nor '"entries"' nor 'MRCLEAN:' plaintext markers (magic 'MRCLNMAP' IS expected)
    - modes (POSIX): key file 0o600, map file 0o600, keys dir 0o700, sessions dir 0o700 (stat & 0o777 asserts; skip on win32)
  </behavior>
