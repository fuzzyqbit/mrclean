<objective>
Close both 08-UAT.md gaps (UAT test 2, one major + one cosmetic), both pinned to root cause:

1. **major** — `mrclean install` crashes with a raw Node ENOENT stack on a machine where `$HOME/.claude` does not exist. `atomicWriteJson` (src/install/atomic-json.ts:40-56) writes its tmp file into `dirname(target)` without ensuring the directory exists; the settings-write path never mkdirs `~/.claude` (unlike src/install/ignore.ts:99 and src/install/project-dir.ts:78, which both use `mkdir(..., { recursive: true })`). Pre-existing defect (predates Phase 8) surfaced by fresh-HOME UAT — every existing install test pre-creates `.claude` in beforeEach (tests/install/idempotency.test.ts:23), so the suite never saw it. This violates the PROJECT.md zero-config-first-run distribution constraint and the error-handling rule.

2. **cosmetic** — the install success banner hardcodes `' (hooks: 4, MCP server: mrclean)'` at src/install/index.ts:81 while 5 hook events are registered (08-02 widened HOOK_EVENTS to 5 and the banner was missed). The count must derive from `HOOK_EVENTS.length` — which requires exporting `HOOK_EVENTS` from settings.ts (currently module-private at line 19).

Purpose: TDD fits both — crisp input/output pairs (target-in-missing-dir → written file; install run → banner count equal to registered-event ground truth), and the RED tests reproduce the exact UAT observations offline before any fix lands. One plan, not two: same subsystem (src/install/), same UAT test, one shared observable flow (a fresh-HOME install that succeeds prints the banner); a standalone banner plan would be far below minimum task size.

Output: fresh-HOME `runInstall` resolves cleanly and registers 5 events; the banner reads `(hooks: 5, MCP server: mrclean)` derived from the constant; 3 new tests lock both behaviors; dist rebuilt and committed as a separate chore per repo convention.
