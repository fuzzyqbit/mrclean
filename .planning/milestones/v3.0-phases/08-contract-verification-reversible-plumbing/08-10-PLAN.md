Close the builder half of 08-VERIFICATION.md gap 1 (review CR-01, Critical — independently reproduced by the verifier): `buildE1` in tests/uat/findings-builder.ts assembles E1 per-tool records and the E1 verdict string exclusively from `run.e1Tools` with a not-run stub fallback and NO fallback to the previous artifact's `E1.tools`. Any partial rerun that records at least one verdict elsewhere (e.g. `vitest -t 'E2'`, or a Claude Code upgrade run where the E1 legs fail at assertSessionRan while later legs succeed) passes the zero-verdict guard and rewrites the committed E1 verdicts "Bash: ignored (...); Read: ignored (...); MCP: honored" to "Bash: not-run; Read: not-run; MCP: not-run" — destroying the per-tool evidence that HOOK-CONTRACT.md §E1, THREAT_MODEL.md, and the src/shared/types.ts JSDoc cite. Purpose: TDD is the right tool here — partial-rerun scenarios have crisp input/output (previous artifact + RunRecords in, merged experiments out), and the existing unit suite missed the defect precisely because its `previousArtifact()` fixture uses `tools: {}`. Writing failing tests against populated prev tools FIRST proves the durability fix is real, offline, before any live run can touch the committed artifact.

Output: `buildE1` carries per-tool records forward (fresh -> previous -> stub) and derives the E1 verdict string from the merged tool map; the offline unit suite covers partial-rerun scenarios with populated previous E1.tools. Zero live tokens spent.
